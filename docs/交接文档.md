## 1. 项目一句话

Windows 本地单张生图工作台：PySide6 桌面 + REST + MCP + **OpenAI Images 兼容层（/v1）** +
**ComfyUI 协议网关（/comfyui）** 三类对外接口，共享同一 SQLite 任务队列；双引擎——
ComfyUI 0.3.76（sd15 / sdxl-lightning / z-image-turbo，仅文生图）与
**MOSS-Image / FLUX.1-Kontext dev（sd-cli 独立进程，runner=moss/sdcpp，文生图 + 图生图）**。

dsh-image-gen 插件已通过 **openai-compat 渠道**接入（baseURL `http://127.0.0.1:12138/v1`，
model 即工作流 ID），不再依赖工作流 JSON 与 ComfyUI 端口。

## 3. 工作流能力矩阵（当前）

| workflow_id | runner | 图生图 | 尺寸 |
|---|---|---|---|
| moss-image | moss（1.1.0） | ✅ strength 默认 0.5 可传参 | 512²/768²/768×1024/1024×768/1024² |
| kontext-dev | sdcpp（1.0.0） | ✅ 参考图必选 | 1024² |
| qwen-image-21 | sdcpp（1.0.0） | ✅ 参考图可选、指令式编辑、**无 strength** | 1024² |
| z-image-turbo / sd15 / sdxl-lightning | comfy | ❌（提交 image/strength → 422） | 见维护日志 §0.3 |

能力由 **manifest 的 `[inputs]` 声明**（`image`/`strength` 已入白名单），UI 与 API 自动跟随。
`required_inputs`（目前只有 kontext-dev 声明 `["image"]`）在 `Workflow.parameters()` 里就拦：
缺参考图 → 422 `REQUIRED_INPUT_MISSING`，不会先进引擎再白跑一次（桌面禁用生成只是前置提示）。

## 4. 踩过的坑（每一条都真实发生过）

1. **`Set-Content` 默认编码是 ANSI**——写含中文的文件必须 `-Encoding UTF8`，
   否则 Python 脚本报 SyntaxError（kontext_verify 踩过）。
   **反过来也成立**：Windows PowerShell 的 `-Encoding UTF8` 会加 **BOM**，而
   `config.toml` 是 `tomllib` 解析的，带 BOM 直接 `TOMLDecodeError`——打包版
   `--windowed` 没有控制台，表现是**启动 30 秒后静默退出、API 端口不监听**（2026-11-09
   改 `job_timeout` 时踩到）。改配置一律用
   `[IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($false)))`。
2. **pwsh 后台任务被杀会连带杀掉它启动的子进程**——长驻服务要用
   `Invoke-CimMethod Win32_Process Create` 分离启动（main-app.pid 记录法）。
   我曾因此误杀用户的 moss 任务。
3. **`taskkill`（WM_CLOSE）现在只会让桌面版缩托盘**（托盘常驻是功能）——
   自动化关闭必须 `taskkill /F`，或托盘菜单退出。
4. **PowerShell 里 `*> 重定向 + 脚本内 $ErrorActionPreference='Stop'`** 会让
   PyInstaller 的 stderr INFO 行变成终止错误——构建必须经
   `Start-Process powershell -File tools\build-windows.ps1 -RedirectStandardOutput/-Error` 子进程方式。
5. **编辑工具对大段中文代码块的 old_string 匹配会莫名失败**（字节层面一致也失败）——
   大块替换改用 Python 锚点正则脚本（`.runtime/fix_comfy.py` 模式，带断言）。
6. **锚点正则替换会吞掉区间内的方法**——fix_comfy.py 曾把 `queue()` 方法连同旧代码
   一起吞掉，导致所有 comfy 任务全灭。对策：`tests/unit/test_engine_surface.py`
   守卫引擎类方法表面；替换后必须 `Select-String` 复核。
7. **QSpinBox 在 zh_MO 区域格式下显示苏州码子**（8765 → 〨〧〦〥）——
   端口框已固定 `QLocale.c()`，新增数字输入框同样要设。
8. **`Get-NetTCPConnection` 在本机不可靠**（监听存在却查不到）——
   服务探活一律用 HTTP 探测（httpx/Invoke-WebRequest）。
9. **python-multipart==0.0.33** 是 multipart 解析依赖（已在 lock），删了 /v1 编辑和上传就崩。
10. **HF 大文件下载**用 `.runtime/kontext_fetch.py` 模式（curl 分片 + 12 线程 + LFS sha256 校验），
    直连会频繁 TLS 断连。
11. **PySide6 的 multipart 必须自己保活**——只靠 reply 的父子关系，`QHttpMultiPart`
    会在事件循环里被 GC，实测直接 access violation（进程退出码 -1073741819）。
    客户端用 `_inflight` 持有 `(reply, multipart)` 直到 `finished` 才释放。
12. **Qt 槽函数里漏 import 会静默吃掉回调**——`desktop/client.py` 少 import
    `Path/QFile/QIODevice/QHttpMultiPart` 时，点「选择图片」立刻 NameError，
    界面永远停在"上传中…"，只有 `logs/localgen.log` 里一行 traceback。
    凡是"点了没反应 / 一直加载中"，先翻应用日志再猜网络。
13. **参考图只裁不拉，口径只有一处**：`localgen/imaging.py` 的 `cover_box` /
    `normalize_reference` / `reference_png` 同时供桌面预览、Kontext `stage_reference`、
    MOSS `--init-img` 使用。改参考图行为改这一处；别在引擎里各写一份
    （旧实现是 `resize((w,h))` 直接拉伸，3:2 照片喂 1024² 会把脸压扁）。
14. **能力声明 ≠ 拦得住**：`JobService.submit()` 里 `workflow.parameters()` 先于引擎检查执行，
    所以必填输入校验必须写在 `Workflow.parameters()`（`REQUIRED_INPUT_MISSING`）。
    只锁 UI 按钮时，REST / `/v1` / `/comfyui` / MCP 仍会收下无参考图的 kontext 任务，
    202 入队后白烧一次 GPU 才在引擎里 `INVALID_INPUT_IMAGE` 失败（实测）。
15. **改 `config/default.toml` 的默认值对已有数据目录无效**——`%LOCALAPPDATA%\LocalGen\config.toml`
    是首次启动时合并出来的**完整快照**，之后只读它。今天 `job_timeout` 600→1200 就踩到了：
    qwen 参考图编辑实测 604 秒，旧上限把正常任务判成 `JOB_TIMEOUT`（打包版 13:30 构建实测确认）。
    改默认值后，**必须同时手改老数据目录的 config.toml**，否则新默认值不会生效。
16. **`PATH` 里的 `python` 是 WindowsApps 的占位 exe**——`Get-Command python` 指到
    `...\WindowsApps\python.exe`（0 字节 stub），跑起来 **exit 9009、一个字符都不输出**，
    连 `Tee-Object` 都不会建日志文件。冒烟/测试/探测一律显式用
    `.\.venv\Scripts\python.exe`（2026-11-09 因此白丢两次 qwen 冒烟，还误以为任务没提交）。
17. **别用键鼠自动化去驱动 LocalGen 的窗口**——后台进程调 `SetForegroundWindow` 会被
    Windows 前台锁拒绝（返回 False），随后的 `SendKeys` 就打进**当前前台窗口**（真机上
    直接敲进了用户的 DSH 会话输入框）。要验证「能力 → 控件状态」用离屏脚本
    `.runtime/ui_capability_matrix.py`（`QT_QPA_PLATFORM=offscreen` + 真实 `Window`），
    要截界面图用 `windows_computer_use_screenshot(nativeWindowHandle=…)`（PrintWindow
    不需要前台，但窗口**最小化时只能截到 146×28 的残影**，必须先 `ShowWindow(SW_RESTORE)`）。
    截**完整界面（含历史/详情/空状态）**用 `.runtime/shot_ui2.py <job.json> <out.png> <宽x高> [empty]`，
    它会把真实历史列表也灌进去（只 `show_job` 拍出来列表是空的，容易误判布局）。
18. **sd-cli 的采样分母不等于 `--steps`**——图生图按 `strength` 推 `t_enc`，日志明写
    `target t_enc is 30 steps`，真机跑出来是 `31/31`，而 manifest 写的是 50 步。
    任何"分母 == steps 才算采样"的判定都会把整段采样误标成加载权重（批次 1 踩过）。
    正确判据：**带 `s/it` / `it/s` 的是采样，带 `GB/s` 的是加载**。
19. **sd.cpp 的显存不足不说 `out of memory`**——它报
    `model manager cannot make enough memory available on CUDA0`、
    `failed during workspace capacity check`、`failed during allocated capacity check`
    三种措辞（前两句与后两句分别在不同任务上实测）。只匹配 CUDA 那句会让真 OOM 落成笼统的
    `ENGINE_EXECUTION_FAILED`（6 GB 卡跑 768×1024 + 参考图就是这条）。
20. **PowerShell 里用 `(Get-Content ...) -replace ... | Set-Content -NoNewline` 会毁掉整个文件**——
    `Get-Content` 返回行数组，`-NoNewline` 把换行全吃掉，整个 `.py` 变成一行
    （本会话真的把 `desktop/__init__.py` 合成过一行，靠上下文原文重建）。改文件一律用
    `edit` / `write` 工具，或 Python 读写；别用管道拼文件。
21. **sd-cli 的 `ETA` 不能透传**——它按**累计均值**推，首帧那笔冷启动（4.5 s/it vs 常态 1.9）
    能把真实剩余 100 s 说成 222 s（+121%），31 步那跑甚至 +306%。自己算：
    丢首步 + 近 8 步均值 + 不足 2 笔不显示，误差落到 10 s 内（三份日志回放 8.8/2.5/1.3 s）。
22. **`ui.json` 只在正常退出时写**——`shutdown()` / 托盘"退出" / 设置里"保存并退出"三处调
    `save_ui()`。`taskkill /F` 杀掉不会落盘；**`WM_CLOSE`（点右上角 ×）走的是"隐藏到托盘"
    分支，也不写盘**。验证布局记忆必须走托盘右键"退出"或 `real_exit=True; close()`。
23. **手改配置文件会带 BOM，而 `utf-8` 读不了它**——记事本 / VS Code / PowerShell 5.1 保存
    `config.toml` 与 `ui.json` 时都会加 BOM。前者让 `tomllib` 报
    `Invalid statement (at line 1, column 1)`、打包版**静默起不来**；后者让 `json.loads`
    抛 `ValueError` 被"文件不存在"的兜底吞掉、**布局静默丢失**。两处读取都已改 `utf-8-sig`。
    写文件仍用无 BOM（`atomic_write` / `json.dumps` 直写字节），所以自己的写入不受影响。
