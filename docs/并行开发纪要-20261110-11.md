## 三、pose-swap 两段式流水线（本轮核心）

**问题**：姿势+服装同时选中时"衣服换了、姿势没换"——同种子对照实测确认：
换装是局部编辑（低风险），换姿势是全局重排（高风险），单段生成两指令竞争时模型
永远走低风险路径。插件原版本就是两段流水线。

**方案**（`engine/sdcpp.py` `PoseSwapJob` + `engine/comfy.py` `observe_sdcpp`）：

- 姿势段（人物图+骨骼图 → `stage-pose.png`）→ 换装段（中间产物当人物图 + 服装参考
  → `image.png`），段间由引擎观察循环自动接续，一次提交、调度器 / REST / MCP 无感
- 姿势 LoRA 只挂姿势段；两段共用提交种子；进度 detail 带「姿势段 · / 换装段 · 」前缀；
  分段日志 `sdcpp-<id>-s1.log` + `sdcpp-<id>.log`
- 真机验证：一次提交两段自动接续 succeeded；首跑踩掉两个 bug（分段日志名未挂 job、
  段落前缀叠加）均已修复并加测试锁

## 四、分段步数 + 默认 15 步

- Submission 新增 `pose_steps` / `garment_steps`（1–25，仅 pose-swap 1.1.0+ 声明，
  其他工作流 422）；桌面「分段步数」行、zcode 插件分段输入均已透传
- **默认 8 → 15**：用户实测 8 步出图偏模糊；turbo 是固定 8 档 sigma 表，15 步自动
  回落 euler 常规 schedule（模板已移除 sigmas 死字段，显式 8 步仍可用预设）
- 插件占位动态推导 `默认(${engine_parameters.steps})`，以后改模板步数插件零改动；
  pose-swap 模式下通用步数框隐藏（提交/校验/历史重跑三处隔离，残留值不再变成
  两段的隐形基线）
