# LocalGen 维护日志

> 长期维护文档。记录接口基线与历次变更，让任何时刻打开本工程的人（或 AI 助手）
> 能快速知道"现在接口长什么样、最近改了什么、大功能走到哪一步"。
> 项目整体介绍见 [项目说明](项目说明.md)。

## 使用约定

**记什么**：任何影响对外接口（REST / MCP / 工作流 / 配置 / 存储 schema / CLI / 打包产物）
或行为语义的改动；纯文档修订也简要记录。

**记在哪**：

- **A 区 · 近期的小功能接口与修改**：参数与字段级调整、错误码增删、小工具脚本、
  文档修正、UI 文案、工作流同版本的尺寸白名单增补、依赖小版本等。**最新条目在顶部，倒序追加。**
- **B 区 · 大功能接口与修改**：新工作流（尤其新 runner/引擎）、REST 契约破坏性变更、
  MCP 工具增删、引擎版本锁定变更、存储 schema 迁移、打包方案变更、安全模型变更。**同样倒序。**
- 判定口径：**需要重新部署 / 需要迁移 / 改变对外契约语义 → B 区**；其余 → A 区。
  一批 A 区小改动累积改变了契约语义时，在 B 区立条目，A 区保留一行指针。

**条目格式**（保持一致，方便日后检索）：

```text
### YYYY-MM-DD · 标题                       ← A 区条目
- 范围: api / engine / workflows / storage / desktop / config / tools / docs
- 变更: 做了什么、为什么
- 接口影响: 无 ｜ <具体变化>
- 验证: pytest ｜ 手工步骤与结果

### YYYY-MM-DD · 标题   [状态: 进行中｜已交付｜已关闭]   ← B 区条目
- 动机:
- 接口影响: REST / MCP / 工作流 / 配置 / 存储 / 打包，逐项列出
- 部署物与迁移: 新增文件、模型、数据目录变化、用户需要的操作
- 验证: 自动化测试 + 实机记录（链接 benchmark.md）
- 遗留: 清单；全部清零后状态改「已关闭」
```

**纪律**：

- 改动完成后**当天**补条目；B 区条目在"遗留"清零前不得标已关闭。
- 每次接口变化时**同步更新 §0 基线**（改动行尾标注日期），基线末尾的"最后核对"日期一并更新。
- 实测数据（耗时、显存、尺寸白名单依据）一律沉淀到 [benchmark.md](benchmark.md)，条目里放链接。

### 2026-11-09 · 预览立即显示 + 两处 BOM 容错 + 批次 5 桌面端 + 快捷方式

- 变更:
  - **预览图选中即显示（用户报告的 bug）**：`paint_image()` 原来用 `self.image.size()`
    算缩放框，但选中历史时 image 标签刚从隐藏切到可见、布局尚未重新分配，取到的是隐藏前
    的旧尺寸（甚至 1×1）→ 图被缩成一个点，要等窗口 resize 触发 `eventFilter` 重绘才正常。
    改用 `self.canvas.size()`（画布始终可见）。同时 `show_canvas(True)` 改成

    同一任务会留一个空白框。
  - **`config.toml` 带 BOM 容错**：`load_settings()` 改用 `read_text("utf-8-sig")`。
    原来带 BOM 时 `tomllib` 报 `Invalid statement (at line 1, column 1)`，打包版
    `--windowed` 没有控制台，用户看到的是"双击没反应"。另外把 TOML/字段错误包成

    UTF-8（无 BOM）或删掉重建"的处理办法。

## C · 常用维护操作清单

**新增 / 修订工作流**
1. 建 `workflows/<id>/<semver>/`：manifest.toml + prompt.api.json；对模板算 SHA-256 填 `template_sha256`。
2. `output_node` 必须 SaveImage；inputs 只用白名单键；models 与模板一致；小尺寸先行实机验证，
   `verified_sizes` 只放通过的档位。
3. 补测试（新 runner 必须有）；`pytest -q`；`build-windows.ps1` 重打包；B 区立条目
   （同 workflow_id 新版本自动成为 current，旧版本目录要保留——老任务按原版本执行）。

**修改 REST / MCP 契约**
1. `jobs/models.py`（pydantic）→ `api/app.py` → `mcp/__init__.py` 三处同步。
2. 破坏性变更走 B 区大功能流程，评估 `/api/v1` → `/api/v2`；非破坏性记 A 区。
3. `tests/integration` 补用例；`tools/verify-engine.py` 同步；更新 [项目说明 §3](项目说明.md) 与本文件 §0.1。

**修改配置键**
1. `config.py` Settings（含范围校验）+ `config/default.toml` 同步。
2. 注意 `extra=forbid`：**移除或改名键**会让旧数据目录的 config.toml 启动报错，条目里必须写迁移说明。

**重新打包**
1. `pytest -q` 全绿 → `tools/build-windows.ps1` → 用 dist 包冒烟（`--headless --mock` 或真实引擎）。
2. 核对 `dist\LocalGen\_internal\workflows` 包含全部工作流；dist 作为整体目录分发。

**升级引擎（ComfyUI / sd-cli）**
1. 新版本先隔离验证：独立数据目录 + `--engine-root` 指向新 portable。
