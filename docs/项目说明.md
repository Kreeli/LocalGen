# LocalGen 项目说明

> 本文描述 LocalGen 的定位、架构、接口与运行方式，供新人或 AI 助手快速熟悉工程。
> 接口的当前快照与历次变更记录见 [维护日志](维护日志.md)（接口以该文档 §0 基线为准）；
> 安装与打包见 [Windows 安装手册](windows-setup.md)，实机数据见 [验收记录](benchmark.md)。
>
> 最后更新：2026-11-09

## 1. 定位

Windows 11 上的**本地单张文生图服务**：单用户、单机、全部端口绑定回环。
PySide6 桌面界面、REST、MCP 三个入口共享同一份 SQLite 任务历史，可提交、取消、查询进度、下载 PNG。

核心场景之一：**为不具备文生图能力的 AI 客户端提供统一的本机生图端口**——
AI 通过 REST 或 MCP 提交任务 → 轮询状态 → 用返回路径下载 PNG。

硬件基线：NVIDIA RTX 4050 Laptop（6 GB 独显）、Ryzen 7 7735、16 GB 内存。
V1 范围仅单张文生图；图生图、批量、远程访问、模型市场均不在范围内。

## 2. 总体架构

```text
本机 REST 客户端（含其他 AI 程序）────┐
本机 MCP 客户端（AI 工具）── /mcp ───┤
PySide6 桌面 ── QNetworkAccessManager ┤
                                      ▼
        LocalGen 进程（Qt 主线程 + 单个 FastAPI/Uvicorn 服务线程）
        应用服务 → SQLite 任务库 + 持久 FIFO → 单个调度器（asyncio 任务）
                                                    │ 127.0.0.1:8188 HTTP/WS
                                                    ▼
                              ComfyUI 0.3.76 子进程（自有 Python 环境）
                              或 MOSS 模式：sd-cli.exe 独立进程（见 §5.2）
```

要点：

- Qt 主线程只做交互；API 生命周期内持有调度器、数据库、MCP 会话管理器、引擎管理器。
- **SQLite 是唯一事实来源**（WAL、外键、busy timeout 3s），持久 FIFO 按 seq 取最早 queued 任务；
  部分唯一索引保证同一数据目录**同时只有 1 个活动任务**；实例锁保证单 LocalGen 进程。
- ComfyUI 拥有自己的 Python/PyTorch 依赖，LocalGen 只装应用依赖；两者仅通过 ComfyUI 公开服务接口通信。
- 端口默认 8765（LocalGen）/ 8188（引擎），冲突即报错，绝不接管占用端口的未知进程。

## 3. 对外接口

### 3.1 REST（前缀 `/api/v1`）

除 `GET /health` 外均需 `Authorization: Bearer <令牌>`；Host/Origin 白名单校验；请求体上限 64 KB。

| 方法及路径 | 契约 |
|---|---|
| GET /health | 存活探针，免鉴权，引擎不可用时仍返回 200 |
| GET /engine | 引擎状态、可用性、脱敏诊断码、当前模式与端口 |
| GET /workflows | 工作流 ID、版本、可用性、缺失依赖、已验证尺寸、支持参数 |
| GET /workflows/{id}/dsh-plugin | 导出 dsh-image-gen 兼容工作流 JSON（`variant=text2image` 默认 / `image2image`）；attachment 下载；moss 导出为网关专用图 |

另有 `/comfyui/*` ComfyUI 协议兼容网关（`/prompt`、`/history/{id}`、`/view`、
`/upload/image`、`/system_stats`）：免 Bearer 令牌（回环限定，Host/Origin 校验保留），
把导出的工作流图映射回 LocalGen 任务队列，使 dsh-image-gen 等 ComfyUI 客户端
能用包括 moss 在内的全部工作流。网关基址 `http://127.0.0.1:<api端口>/comfyui`。

另有 `/v1/*` OpenAI Images 兼容层（标准 Bearer 令牌）：`GET /v1/models`、
`POST /v1/images/generations`、`POST /v1/images/edits`——`model` 即工作流 ID，
同步返回 `data[0].b64_json`；这是面向外部工具的推荐接口（OpenAI 事实标准，
dsh-image-gen 经 openai-compat 渠道接入，无需工作流 JSON）。
| POST /jobs | 202 + Job，`Location` 指向任务详情；支持 `Idempotency-Key` 头 |
| GET /jobs | `status`、`limit`（默认 20，上限 100）、不透明 `cursor`；按创建倒序 |
| GET /progress | 当前活动任务（submitting/running/cancelling，含 progress）与 queued 数量；空闲时 `{"job": null, "queued": 0}` |
| GET /jobs/{job_id} | Job 全量，含终态错误或成品元数据 |
| DELETE /jobs/{job_id} | 删除终态任务及其成品文件与引擎遗留输出；活动任务 409，未知 404 |
| POST /jobs/{job_id}/cancel | 活动任务 202，排队取消/已取消 200，已终态 409 |
| GET /jobs/{job_id}/artifacts/{artifact_id} | 下载 PNG（`inline`，`no-store`） |

提交体（未知字段 422，`extra=forbid`）：

```json
{
  "workflow_id": "moss-image",
  "prompt": "雨后街道，暖色窗灯",
  "width": 768, "height": 768,
  "seed": 42,
  "negative_prompt": "可选，仅支持该输入的工作流"
}
```

校验：prompt 去首尾空白后 1–2000 字符；宽高必须成对且命中工作流 `verified_sizes`；
seed 0–4294967295，省略时服务生成并保存实际值；像素数不超过 `max_pixels`；
可选 `image`（gateway-input 中 32 位 hex 文件名，仅声明图生图输入的工作流可用，
如 moss-image）与 `strength`（0–1 重绘强度，仅与 image 同时可用）；
未知字段 422（`extra=forbid`）。
幂等键：同键同参返回原任务，同键异参 409 `IDEMPOTENCY_CONFLICT`。

错误模型统一为 `{"error":{"code","message","retryable"}}`。错误码按状态码分组：

| 状态 | 错误码 |
|---|---|
| 401 | UNAUTHORIZED |
| 403 | LOCAL_POLICY_DENIED |
| 404 | JOB_NOT_FOUND · WORKFLOW_NOT_FOUND · ARTIFACT_NOT_FOUND · HTTP_ERROR |
| 409 | IDEMPOTENCY_CONFLICT · JOB_TERMINAL |
| 413 | REQUEST_TOO_LARGE |
| 422 | VALIDATION_ERROR · UNSUPPORTED_PARAMETER · UNSUPPORTED_SIZE · INVALID_CURSOR · INVALID_IMAGE · INVALID_IMAGE_PATH |
| 429 | QUEUE_FULL |
| 500 | INTERNAL_ERROR |
| 503 | ENGINE_UNAVAILABLE · ENGINE_NOT_CONFIGURED · ENGINE_PATH_INVALID · ENGINE_VERSION_UNSUPPORTED · ENGINE_WINDOWS_REQUIRED · ENGINE_PORT_IN_USE · ENGINE_LISTENER_INVALID · ENGINE_START_TIMEOUT · ENGINE_LAUNCH_FAILED · ENGINE_EXITED · ENGINE_STOP_UNCONFIRMED · ENGINE_PREVIOUS_INSTANCE_UNCONFIRMED · ENGINE_HEALTH_FAILED · ENGINE_REJECTED_PROMPT · ENGINE_EXECUTION_FAILED · ENGINE_RESULT_LOST · SUBMISSION_UNKNOWN · JOB_TIMEOUT · JOB_INTERNAL_ERROR · WORKFLOW_REVISION_MISSING · WORKFLOW_DEPENDENCIES_MISSING · WORKFLOW_NOT_VERIFIED · GPU_OOM · DISK_SPACE_LOW · SERVICE_STOPPING |

（另有 `APP_RESTARTED` 作为 interrupted 任务的落库错误，不出现在 HTTP 状态里。）

### 3.2 MCP（Streamable HTTP）

端点 `http://127.0.0.1:8765/mcp`，无状态 JSON 响应模式，DNS rebinding 防护开启。
客户端配置：传输类型选 **Streamable HTTP**，地址如上，请求头 `Authorization: Bearer <令牌>`。

| 工具 | 输入 | 返回 |
|---|---|---|
| list_workflows | 无 | 工作流能力与可用性 |
| generate_image | 同 POST /jobs + 可选 idempotency_key | 立即返回 Job |
| get_job | job_id | Job（含结果下载路径） |
| list_jobs | status / limit / cursor 可选 | 分页结果 |
| cancel_job | job_id | 取消后的 Job 或结构化错误 |
| delete_job | job_id | 删除已结束的任务及其成品图片 |

六个工具与 REST 走同一套应用服务、校验与错误码；跨 MCP 调用的长任务用 get_job 轮询，或直接轮询 GET /progress。

### 3.3 任务模型

```text
queued → submitting → running → succeeded
   │         │          ├──────→ failed
   │         ├──────────┴──────→ cancelling → cancelled / failed
   └─────────→ cancelled
submitting / running / cancelling → interrupted（重启时无法确认结果）
```

- 调度器单活动任务：条件更新认领最早 queued；提交超时按结果未知处理（回收引擎，不盲目重发）。
- 取消：queued 直接落库；submitting/running 先写 cancelling 再经引擎确认；与成功竞争时条件更新仲裁。
- Job 字段：job_id、status、workflow_id、workflow_revision、parameters（实际值）、created_at、
  started_at、finished_at、progress、artifacts[]、error。时间 UTC ISO 8601。
- progress：`{"stage":"sampling","current":n,"total":m}`，可为 null。
- artifact：artifact_id、mime_type、width、height、size_bytes、download_path、available。API 不暴露磁盘绝对路径。
- 成品交付：PNG 严格校验（单帧、尺寸一致、≤ max_image_mib）→ staging 暂存 → 同卷原子移动到
  `results/<job_id>/<artifact_id>.png` → 事务写库置 succeeded；启动时对账，孤儿文件隔离到 quarantine。

## 4. 工作流体系

每个工作流是**经审查、不可变版本**的 ComfyUI API 图：`workflows/<workflow_id>/<semver>/`
下 `manifest.toml`（元数据与映射）+ `prompt.api.json`（API 图，SHA-256 写入 manifest 的
`template_sha256` 锁定）。入队即固定版本与摘要；工作流升级后旧任务仍用原版本执行，
原版本目录缺失则以 `WORKFLOW_REVISION_MISSING` 失败。

- `engine`：`comfy`（真实引擎）或 `mock`（演示）；`runner`：`comfy`（默认）或 `moss`（§5.2）。
- inputs 映射白名单：`prompt / negative_prompt / width / height / seed / output_prefix`，
  只允许渲染模板中已存在的字段；`output_prefix` 恒为 `<job_id>/image`。
- 模型依赖在 manifest 中声明（节点、字段、文件名），就绪检查同时核对 `/object_info`
  中的节点与模型选项；MOSS 工作流另有文件大小钉死校验（§5.2）。
- 当前注册表（含验证状态）见 [维护日志 §0.3](维护日志.md)。

## 5. 引擎管理

### 5.1 ComfyUI 路径（runner=comfy）

- 版本硬锁定 **0.3.76**：读 `comfyui_version.py` + 启动后核对 `/system_stats`，不符即 503。
- 启动参数：`-s -u main.py --listen 127.0.0.1 --port … --cuda-device … --disable-all-custom-nodes
  --disable-api-nodes --disable-metadata`，output/temp/input/user 目录全部重定向到数据目录下的
  `comfy-*` 文件夹；输出目录按 job_id 分子目录。
- **GGUF 白名单**：`custom_nodes/localgen_gguf` 五个源文件 SHA-256 全部匹配（city96/ComfyUI-GGUF
  fa48477）才加 `--whitelist-custom-nodes`，否则该加载器不可用。
- 进程管理：WinAPI `CreateProcessW` + **kill-on-close Job Object**（进程出生即在 Job 内）+
  匿名管道排水日志；`engine-identity.json` 记录 pid/创建时间，重启时等待上一代引擎确认退出。
- 健康模型：监听归属校验（GetExtendedTcpTable 核对 127.0.0.1 与自有 pid）→ `/system_stats` →
  NVIDIA CUDA 设备 → `/object_info`；就绪后每 5s 复检。失败按 2^n（上限 15s）退避重启，最多 4 次；
  路径/版本/设备类错误为永久失败不重试。
- 观察：`/prompt` 提交拿 prompt_id → `/ws` 进度事件 → `/history/{prompt_id}` 判定 → `/view` 拉图。
  返回文件名必须匹配 `image_\d{5,}_.png` 且 subfolder=job_id，否则视为不受控路径。

### 5.2 MOSS 双引擎路径（runner=moss）

`moss-image` 不走 ComfyUI 推理：提交时**先停掉 ComfyUI 释放显存**，直接运行
**stable-diffusion.cpp（0b3b98d）`sd-cli.exe`**，出图后回收进程并重启 ComfyUI。

- 部署根：`<engine_root>/localgen-moss/`，`bin/`（sd-cli 与 CUDA12 DLL，8 个文件名钉死）+
  `models/` 四件套（文件名 + 字节数钉死校验，缺失即 `WORKFLOW_DEPENDENCIES_MISSING`）。
- 关键参数：`--backend diffusion=cudaN,te=cpu,vae=cudaN`（9B 文本编码器走 CPU）、
  `--max-vram -1`、`--flash-attn auto`、`--threads 6`、`--mmap`；
  prompt/negative 写入任务私有 UTF-8 文件再以 `--prompt-file` 传入，避免出现在命令行与日志。
- 生命周期：submit_moss（校验→停 ComfyUI→启动 sd-cli，状态 `MOSS_ACTIVE`）→
  observe_moss（进程存活则回进度；退出则 recycle + 读 `image.png`，识别 OOM）→
  cancel 等价于 recycle（终止 sd-cli）。1.1.0 起支持图生图：`image` 引用
  `gateway-input` 中的上传图按私有文件模式复制进任务目录，命令追加
  `--init-img`/`--strength`（默认 0.5，可经 `strength` 参数调节）。
- 模型来源（URL + SHA-256）锁定在 `.runtime/moss-download.log`。
- **注意**：16 GB 内存几乎打满（1024×1024 时最低可用仅约 125 MiB），MOSS 出图期间应避免其他大内存负载。

### 5.3 演示引擎（mock）

`engine_mode="mock"`（或 `--mock`）时以 Pillow 程序绘图替代真实引擎，任务照常入历史，
用于无模型/无 GPU 环境的功能验收。mock 模式只暴露 `baseline` 工作流。

## 6. 数据与安全

数据目录（默认 `%LOCALAPPDATA%\LocalGen`，可用 `--data-dir` 指定）：

```text
<数据目录>/
├── config.toml                 # 首次启动从 config/default.toml 复制，可关闭应用后手改
├── api-token.bin               # Bearer 令牌，Windows DPAPI 加密、绑定当前用户
├── instance.lock               # 单实例文件锁
├── engine-identity.json        # 引擎进程身份（重启互斥确认，正常退出后删除）
├── jobs.sqlite3 (+-wal/-shm)   # 任务与成品元数据（schema user_version=1）
├── results/<job_id>/<artifact_id>.png
├── staging/                    # 成品发布前暂存（启动时清空隔离）
├── quarantine/                 # 无记录成品/残留文件的隔离区
└── logs/localgen.log           # 轮转诊断日志（1 MB × 3）
```

安全机制：

- 全部监听绑定 127.0.0.1（`SO_EXCLUSIVEADDRUSE`）；ComfyUI 端口仅作引擎内部接口，禁止共用。
- Bearer 令牌高熵随机、DPAPI 存储、`hmac.compare_digest` 比对、日志不落令牌与提示词全文。
- Host/Origin 白名单（默认 127.0.0.1 / localhost）；API 文档与 openapi 关闭、redirect_slashes 关闭。
- `guarded()` 逐级拒绝符号链接与目录联接；`atomic_write` 临时文件 + 原子替换。
- 图片只按数据库 artifact_id 解析到受控路径；PNG 解码用 Pillow 限定格式并防解压炸弹。
- 磁盘余量低于 `min_free_mib` 拒绝新任务；已入队历史不受影响。
- 拒绝调用方提供的任意工作流、命令、远程 URL、任意文件路径与节点安装请求。

## 8. 运行 / 测试 / 打包

```powershell
# 桌面：双击 Launch-LocalGen.cmd（dist 优先，其次 .venv；自动携带项目内 portable 引擎）

# 无界面服务（供其他程序/AI 使用）
.\.venv\Scripts\python.exe -m localgen --headless [--mock] [--data-dir DIR] [--port N] [--engine-root DIR]

# 读取令牌
.\.venv\Scripts\python.exe -m localgen --data-dir DIR --show-token

# 测试（integration 用 mock 引擎；windows 组需真实 Windows）
.\.venv\Scripts\python.exe -m pytest -q

# 打包（产物 dist\LocalGen，onedir 整体分发）
.\tools\build-windows.ps1
```

- 测试分三组：`tests/integration`（REST/MCP 契约、取消竞争、重启保序、隔离对账）、
  `tests/unit`（GGUF 白名单、MOSS 作业）、`tests/windows`（进程树回收、实例锁、桌面离屏）。
- 实机复现命令与基准流程见 [验收记录 §验收复现](benchmark.md)。
- 打包注意：PyInstaller onedir + `--windowed`；用 PySide6 自带 MSVC 运行库覆盖 app-local DLL；
  移除 PATH 里误拾取的 ICU DLL；`_internal/workflows` 必须包含全部工作流目录。
